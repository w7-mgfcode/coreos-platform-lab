## How revisions work here

- The repository has **no commit yet**, so no source in it has a SHA. Documents under `docs/.prepare/` carry **manual revisions** (`r1`, `r2`, …). They are labels maintained by hand, not immutable identifiers: nothing prevents a file from changing without its label changing. The first commit will be the first real anchor. *Note of 2026-11-16 (D-54): the first sentence and the last describe the state when they were written. The initial publication was made later that day, and `main` carries one commit, the bootstrap commit (decision-log r9, D-54). From that commit on, a repository file outside this package can be identified by a commit and a path; the revisions of this package stay manual labels, and no row below was re-read for this note.*
- For repository files outside this package, the column below gives the **date the file was read**. A read date or a retrieval date says when the content was seen. It is **not a revision** and does not identify a version.
- External sources give an upstream commit where one could be read, plus the retrieval date.
- The baseline label that ties the package together is in [README.md](README.md).

## Authority classes

| Class | Meaning |
|---|---|
| binding | Fixes scope or requirements; not reopened by this package |
| governing | Policy this package must follow; changes are proposed, not made |
| record | A faithful account of what was said or done; its statements keep the authority they name |
| reference | A convention to mirror or adapt; says nothing about this project's state |
| upstream | Primary documentation of a tool; evidence about the tool, not about the lab |
| methodology | A way of working; not evidence about this project |
| observation | A command run in this session |
